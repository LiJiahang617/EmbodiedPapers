## 论文主线

这篇论文的核心问题只有一句：**VLA 的跨本体迁移到底卡在哪？** 作者的诊断是——卡在**语义对齐（semantic alignment）**，而不是格式对齐。不同机器人 kinematic（6-DoF vs 7-DoF）、控制接口（joint position vs end-effector pose）、base（fixed vs mobile）、传感器都不同，导致 state/action 空间**异构**：即使你用 zero-padding、per-embodiment normalization，甚至给每个维度指派固定语义角色，把动作塞进“对应维度”，**同一维度（比如 joint 1）在不同机器人上的旋转轴、量程、物理含义还是不一样**。这些 format-level 补丁能让 joint training 跑起来，但没解决“模型是学到了共享可迁移表示，还是只是在统一架构里各自拟合 embodiment-specific 模式”。

作者的关键观察（也是全文赌注）是：**低层 state/action 天生 embodiment-specific，但高层认知过程是跨本体共享的**——感知场景、判断任务进度、规划下一步、识别目标物，一条机械臂从桌上拿杯子的“认知轨迹”，无论它是 6 自由度还是 7 自由度都差不多。这套 embodiment-agnostic reasoning 才是 cross-embodiment pre-training 真正该抓的可迁移知识。

于是 ZR-0 的做法是：**把 ECoT（具身思维链）当成 dense supervision 打进 VLM stream**，逼 System 2（VLM）在预训练时学出语义对齐的表示；System 1（DiT action expert）通过 cross-attention 读这些表示、用 flow matching 生成连续动作块。ECoT 有六个组件，其中 **To-Do Actions**（把计划拆成 embodiment-agnostic 的原子祈使句）被明确指认为“跨本体对齐的关键机制”。

阅读时要盯住的第二个赌注是**推理成本**：ECoT 是一段要 autoregressive 生成的文本，如果推理时也生成它，延迟就爆了。作者用一条 **cross-attention mask** 化解——让 action expert **只 attend VLM 对 input prompt（指令+图像）编码出的特征，屏蔽掉 ECoT tokens**。这意味着：从 action expert 的视角看，ECoT tokens 生不生成、内容是什么，**它根本读不到**，所以“推理时跳过 ECoT 生成而不损失性能”不是靠实验凑出来的，而是**由架构 by-construction 保证的**——ECoT 的价值全部沉淀在预训练学到的 VLM 表示里（Table 5 的 ablation 正是验证这一点）。

一句话概括本文主张：**跨本体迁移的本钱不在动作空间的格式统一，而在高层推理表示的语义对齐；ECoT 就是那把把“共享认知”写进 VLM 的密集监督刻刀，而 attention mask 保证这把刻刀在部署时零成本。**

## 摘要与核心贡献

摘要提出的矛盾是：**VLA 的 cross-embodiment transfer 之所以难，根因是 low-level state/action 空间在不同平台上本质不同**。作者的观察是高层认知（scene perception、object identification、task planning、sub-task decomposition）跨本体基本共享，据此提出 **ZR-0**：一个 **2.6B 参数**的端到端 VLA，用 **dense ECoT supervision** 在 VLM 内对齐跨本体表示。

架构是 dual-stream：**System 2（预训练 VLM）训练时产结构化 ECoT 推理；System 1（DiT-based action expert）用 flow matching 出连续动作块**。二者 cross-attention 耦合，并用一条 **attention mask 把 action expert 限制到 input prompt 特征**，从而**推理时完全跳过 ECoT 生成而不损失性能**。预训练语料是 **ProcCorpus-60M**：约 **60M 帧（~1,000 小时）、>400K 轨迹、96.8% 帧带 dense ECoT 标注**。评测覆盖单臂（LIBERO）、双臂（RoboTwin 2.0）、人形（RoboCasa GR-1 Tabletop）三套仿真 + 真实 xArm。

> 读原文才注意到的两处细节：
> 1. **推理延迟数字自相矛盾**：§3.4 写“单卡 **NVIDIA A6000** bf16 约 **90 ms**”，而 §6 结论写“单卡 **H100** 约 **100 ms**”。GPU 和数字都对不上，引用时需回看原文确认，别混用。
> 2. **“without any performance loss” 的证据性质**：它是**架构推论**（cross-attention mask 让 action expert 永远读不到 ECoT tokens，故生不生成 ECoT 对动作输出无影响），**不是**由“生成 ECoT vs 跳过 ECoT”的对照实验测出来的；论文里唯一相关的消融是 Table 5 的 “w/o ECoT **pre-training**”，那测的是**要不要 ECoT 预训练**，不是**推理时要不要生成 ECoT**。

## 1. Introduction / 为什么 VLA 的跨本体迁移卡在“语义对齐”

作者先把 cross-embodiment transfer 定位成 VLA 范式的“核心承诺”：一个模型吃很多异构机器人的数据，让知识互相迁移。然后指出真正的障碍：不同平台的 kinematic、control interface、base type、sensor setup 都不同，表现为**异构 state/action 空间**——同一维度在不同机器人上物理含义不同。现有做法分两类：(1) format-level 的 zero-padding + per-embodiment normalization；(2) 给每个维度指派固定语义角色以定义统一动作空间。作者的批评很锋利：**即便把动作放进“对应维度”，同一维度（如 joint 1）跨机器人的旋转轴与量程仍不同**——format-level 方案让 joint training 能跑，但没触及 **semantic alignment**。

反过来，高层认知过程（perceiving the scene、reasoning about task progress、planning next steps、identifying target objects）是**跨本体共享**的，这才是 pre-training 该捕获的可迁移知识。ZR-0 据此登场：**用 ECoT reasoning 作为 dense supervision 对齐跨本体表示**，dual-stream（System 1/2）架构，cross-attention 耦合，**ECoT 训练时用、推理时靠 attention mask 完全省掉**。

**这一节读法**：introduction 的价值在于它没有停留在“reasoning 有用”，而是精确到“format-level 对齐 ≠ semantic 对齐”这一层——后面每个方法组件（尤其 To-Do Actions 的 embodiment-agnostic 祈使句、attention mask）都对应 introduction 的一个具体论点，可逐一回勾验证。

## 2. Related Work / 两条线的定位

作者把自己放在两条脉络的交点：

- **VLA 模型线**：从 RT-2 / OpenVLA / FAST 的“连续动作离散化 + autoregressive 解码”（有 sequential decoding 开销、tokenize/detokenize 精度损失），到 π0 的 MoT + flow-matching action expert、π0.5 的 high-level subtask planning、GR00T N1 的 cross-attention DiT action expert。**ZR-0 也是 dual-stream，但区别在于往 VLM stream 里注入 dense ECoT supervision 来改善跨本体表示学习**。
- **VL 数据共训线**：机器人数据贵且少，action-only 微调会侵蚀预训练 VLM 的视觉/语言能力。一类做法混入通用 VL 语料（VQA/caption/OCR/grounding），另一类直接从机器人轨迹构造 **embodied reasoning VL 数据**（scene description、spatial understanding、subtask prediction、motion planning）。**ZR-0 属于第二类，但专注于用 dense reasoning supervision 在异构本体间对齐 VLM 表示**。

## 3. ZR-0 / 方法细节

ZR-0 是 2.6B 端到端 VLA，把 ECoT reasoning 与 diffusion-based action generation 结合，覆盖从单臂（Franka、XArm）到双臂（AgiBot G1、Agilex）的多种本体，训练在 ProcCorpus-60M 上（聚合 Open X-Embodiment、DROID、RH20T 等并自动逐帧标注 ECoT）。

### 3.1 Model Architecture / 双流 + 1:3 交叉注意力 + prompt-only 掩码

**System 2（VLM）**：从 **Qwen3-VL-2B-Instruct** 初始化。给定语言指令 $l$ 与 $n$ 路相机在时刻 $t$ 的图像观测 $o_t=[\text{img}^1_t,\dots,\text{img}^n_t]$，VLM 训练去生成 ECoT 推理序列 $r_t$；实际取**最后一层 hidden states $f_t$** 喂给 action expert。所有图像 resize 到 **224×224**。

**System 1（DiT action expert）**：给定 VLM 特征 $f_t$ 与机器人状态向量 $s_t$，用 flow matching 预测动作块 $A_t=[a_t,a_{t+1},\dots,a_{t+H-1}]$。它由 state encoder、action encoder、一叠 DiT blocks、action decoder 组成（encoder/decoder 都是 MLP）。

DiT block 的关键结构：**一层 self-attention + 三层 cross-attention 的重复模式（1:3）**。
- self-attention 层：state 与 action tokens 之间做**双向注意力**融合特征；
- cross-attention 层：state/action tokens 作 query，**VLM 输出特征作 key/value**；
- **注意力掩码**：把 action expert 限制到**只 attend VLM 中对应 input prompt（指令+图像）的特征，排除 ECoT tokens**。

这条掩码就是“推理时能跳过 ECoT 生成”的根：VLM 对 input prompt 的**一次前向**就能产出 action expert 需要的全部特征，无需 autoregressive 地解码 ECoT。相比 GR00T N1 的 1:1 self:cross 比例，ZR-0 用 **1:3** 提高跨模态交互占比，让 action expert 更充分吸收指令与视觉观测。

### 3.2 Pre-Training Data / ProcCorpus-60M 与 ECoT 六件套

**ProcCorpus-60M** 聚合 >60M 帧（~1,000 小时）、>400K 轨迹，来源含 DROID、Bridge、Fractal、RH20T、若干 Open X-Embodiment 子集等；**96.8% 帧带 dense ECoT 标注**，由自动 VLM 标注流水线（ProcVLM）生成。

每条 ECoT 是六段结构序列，各强化 VLM 的一种能力：

| ECoT 组件 | 内容 | 训练目标 |
| --- | --- | --- |
| **Scene Description** | 当前视觉场景的文字描述 | 提升 object recognition，识别 workspace 中任务相关物体 |
| **Progress Assessment** | 一段“已完成什么”的推理 + 二值完成指示（Yes/No） | 感知 task progress |
| **Future Plan** | 自由文本推理“还需完成什么” | temporal reasoning 与 long-horizon planning |
| **To-Do Actions** | 把 future plan 拆成原子子任务列表，每条 `Verb+Object[+介词短语]`（如“Place the blue plate into the dish rack.”） | **cross-embodiment 对齐的关键机制**：同一子任务分解与底层硬件无关 |
| **Target Objects** | JSON bounding box 定位当前步相关物体（如 `{"blue plate":[120,85,340,260]}`） | visual grounding，把空间注意力导向任务关键区域 |
| **Discrete Actions** | 由 **FAST tokenizer** 产的 embodiment-specific 离散动作 token | 高层 embodiment-agnostic 推理与低层连续控制之间的压缩桥梁 |

**Mixing General VL Data**：额外混入 CapsFusion、Pixmo（VQA/caption/grounding）。与带 ECoT 的机器人数据不同，这些**纯 VL 数据只用标准 language modeling 训 VLM，不涉及动作预测**——用来保住原始预训练的通用视觉感知与语言理解、缓解 catastrophic forgetting，提升对新场景与多样指令的鲁棒性。

### 3.3 Training Objective / 两个损失、各自的梯度归属

两个互补目标：(1) ECoT 的 next-token prediction；(2) 连续动作的去噪向量场预测。

ECoT next-token loss（只更新 VLM 参数 $\theta'$）：

$$
L_{\text{ntp}} = -\,\mathbb{E}_{\mathcal{D}}\!\left[\sum_i \log \pi_{\theta'}\!\left(r^i_t \mid l,\, o_t,\, r^{<i}_t\right)\right]
$$

连续动作块的 flow matching：给定 ground-truth 动作块 $A_t$、高斯噪声 $\epsilon\sim\mathcal{N}(0,I)$、时间步 $\tau\in[0,1]$，构造加噪动作块 $A^\tau_t=(1-\tau)\epsilon+\tau A_t$，训练全模型逼近去噪向量场 $A_t-\epsilon$：

$$
L_{\text{fm}} = \mathbb{E}_{\mathcal{D},\tau,\epsilon}\!\left[\left\lVert \pi_\theta\!\left(l,\, o_t,\, s_t,\, A^\tau_t,\, \tau\right) - (A_t-\epsilon)\right\rVert^2\right]
$$

其中 $\tau\sim\mathrm{Beta}(1.5,1.0)$（偏重更噪的时间步）。总损失：

$$
L = L_{\text{ntp}} + \alpha\, L_{\text{fm}}
$$

**梯度归属是本节最容易被略过的重点**：$L_{\text{ntp}}$ **只更新 VLM 参数**；而 $L_{\text{fm}}$ 的梯度**同时穿过 action expert 与 VLM（经由 $f_t$）**。也就是说，动作损失也在反过来塑造 VLM 特征——ECoT 监督与动作监督并非各管一段，而是共同雕刻 System 2 的表示。

### 3.4 Inference / 前向欧拉去噪、跳过 ECoT

推理时接收 $l,o_t,s_t$，动作块从高斯噪声 $A^0_t\sim\mathcal{N}(0,I)$ 起，用 forward Euler 迭代细化：

$$
A^{\tau+\frac1N}_t = A^\tau_t + \frac1N\,\pi_\theta\!\left(l,\, o_t,\, s_t,\, A^\tau_t,\, \tau\right)
$$

$N$ 是去噪步数，$\tau$ 从 0 起每步加 $1/N$，$N$ 步后 $A^1_t$ 即预测动作块。**ECoT 完全不生成**——绕开昂贵的 autoregressive 文本生成，保留 ECoT 的表示收益却砍掉推理成本：单卡 A6000 bf16 约 **90 ms/action chunk**（§6 结论另称 H100 约 100 ms，见上文口径提醒）。

**这一节读法**：把 §3.1 的 attention mask 和 §3.4 的“跳过 ECoT”连起来看才完整——mask 保证 action expert 的输入与 ECoT 是否生成无关，Euler 去噪只依赖 prompt 特征 + 状态 + 当前噪声动作，因此“跳过”在数值上是无损的。

## 实验（setup / 数据集 / baseline / 指标 / 主结果 / 消融）

### 4.1 Setup

| RoboCasa GR-1 Tabletop | 人形（GR-1） | 24 桌面任务，单模型 | 每任务 100 episodes |
| Real-World xArm | 单臂真实 | >2,000 遥操轨迹、4 任务、50+ 物体、5 Hz | 每任务 10 trials，progress score $S\in[0,100]$ |

**Baselines**：仿真对手随 benchmark 而异——LIBERO 上对比 OpenVLA/CoT-VLA/π0/NORA-1.5/π0.5/GR00T-N1.7/DeepThinkVLA/MolmoAct2；RoboCasa 上对比 GR00T-N1.6/Qwen3PI/VP-VLA/ABot-M0/JoyAI-RA；RoboTwin 上对比 π0/π0.5/X-VLA/Motus/LingBot-VLA；真实 xArm 上对比 π0.5。

**指标**：仿真用 success rate（每 episode 二值）；真实用 progress score（每任务拆子步、按 task-specific rubric 打 0–100）。

**Implementation**：全模型 2.6B = VLM 2.1B（Qwen3-VL-2B-Instruct）+ DiT action expert 0.5B。**预训练**：action chunk $H=32$、global batch 1,024、$\alpha=5$；state/action **zero-pad 到 64 维并 mask 掉 padded 维的 loss**；每维用 1st/99th 分位数 min-max 归一；AdamW（$\beta_1{=}0.9,\beta_2{=}0.95,\epsilon{=}10^{-8}$）；cosine LR + 前 5% warmup，峰值 $3\times10^{-5}$→$3\times10^{-6}$；bf16、grad clip 1.0、DeepSpeed ZeRO + FlashAttention-2 + gradient checkpointing。**Post-training**：batch 64、$\alpha=1$、$H=10$（LIBERO）/$H=16$（RoboTwin/RoboCasa/xArm）；**关键公平性设定——post-training 只用各 benchmark 公开训练数据，不加任何 ECoT 或 VL 共训**，ECoT 与 VL 数据**只在预训练用**。

| 方法 | Spatial | Object | Goal | LIBERO-10 | Avg |

`w/o ECoT PT`：VLM 从 Qwen3-VL-2B-Instruct base 初始化 + 随机初始化 action expert，**直接在 LIBERO 上微调、完全跳过 ECoT 预训练**，post-training 配置相同。结果均值从 97.8 掉到 **95.7（−2.1）**，掉分最重的是 **LIBERO-10（96.4→92.6，−3.8）和 Goal（98.0→94.8，−3.2）**——恰是最吃 long-horizon planning 与目标理解的套件。**这条消融是本文唯一直接证明“ECoT 预训练学到的跨本体表示确实迁移到下游”的证据**；但它只在 LIBERO 上做，且量级不算大（因多套件饱和）。

### 5 Discussion / 作者自陈的三个方向

- **Scaling Robot Data**：当前 ~1,000 小时，比 π0（>10,000h）、LingBot-VLA（~20,000h）、Qwen-RobotManip（>30,000h）低一个量级。数据里充分的技能（pick-and-place）从 ECoT 对齐里获益大，罕见的（关柜/关抽屉）适配弱——扩语料能直接扩大 ECoT 可对齐的技能集；扩动作监督规模或能改善 Hang Cups 那类精细控制。
- **Learning from Human Egocentric Video**：ECoT 的结构化推理对“机器人做还是人做”是 agnostic 的，可用 Ego4D、EPIC-KITCHENS 等海量第一人称视频加 ECoT 标注来扩 VLA 预训练，无需机器人动作标签。
- **Efficient ECoT Annotation**：逐帧 dense 标注很贵（每帧一次 VLM 前向），未来可选“最有信息量的帧”标注，在逼近 dense 表示质量的同时降本。

## 和你的论文库中其他条目的关系

- 对 [[@kang2026x-tokenizer]]（X-Tokenizer）：**互补的两层**。X-Tokenizer 把 action tokenization 重构成“VLA 预训练的语义接口学习”；ZR-0 把 **reasoning** 重构成跨本体对齐的语义接口。而且 ZR-0 的 ECoT 第六段 discrete actions 正是用 **FAST tokenizer**——X-Tokenizer 恰是这条“动作离散化接口”的替代方案。可对读：**“对齐该发生在动作表示层还是推理表示层”**，两者给了互补答案（ZR-0 的原始笔记也点了这条关系）。
- 对 [[@zhang2026qwen-robotworld]]（Qwen-RobotWorld）：**同为 Qwen 系机器人基础模型，但走相反路线**。Qwen-RobotWorld 用 language-conditioned video world model **预测未来视觉轨迹**；ZR-0 用 ECoT dense supervision **对齐 VLM 表示 + 直接出动作**、推理时无未来预测。可对读“跨本体/跨任务的知识该以‘生成未来’还是‘对齐推理表示’的形式沉淀”。（注意：ZR-0 正文对比的 **Qwen-RobotManip [56]**（>30,000h，Yuan 等）**不在当前库**，与本条的 Qwen-RobotWorld 是不同工作，别混。）
- 对 [[@wang2026wvm]]（World Value Model）、[[@yu2026warp-rm]]（WARP-RM）、[[@liu2026steam]]（STEAM）（进度/价值/奖励线）：ZR-0 的 ECoT **Progress Assessment** 组件也在“判断任务进度”，但它把进度当**表示监督**而非**打分/数据筛选信号**。更直接的联系是：ZR-0 的语料 **ProcCorpus-60M 来自 ProcVLM [22]（“procedure-grounded progress rewards”，同组 Feng/Zhang）**——与这条进度奖励线同源，只是 ZR-0 用它做 dense reasoning 标注、而非 reward。ProcVLM [22] 本身**不在当前库**。
- 对 [[@wang2026orca]]、[[@gao2026fast-leworldmodel]]、[[@gigaworld2026roadmap]]（world-model 线）：这些聚焦 latent/visual 世界建模、未来预测与策略评估；**ZR-0 明确不是 world model**——它不预测未来观测，而是把结构化推理当训练监督、推理时是一个快反应策略。它给“要不要显式建模未来”提供了一个反例式对照：**未来可以只作为训练期的 ECoT 文本存在，部署时被彻底省掉**。
- 对 [[@wu2026tactile-wam]]（本库范例）：**方法论上有一个漂亮的平行**——两者都用**非对称的注意力掩码**来控制“某个训练信号能沿哪条路径流动”。Tactile-WAM 的 VideoClean 切断 video-query→tactile-key（保护视觉预测）；ZR-0 的 cross-attention mask 切断 action-query→ECoT-key（让 ECoT 可在推理时省掉）。都是“训练时用、部署/预测时经掩码隔离”的思路，只是隔离对象一个是触觉、一个是 ECoT 文本。
- 对 [[@zhou2026holoagent0]]（HoloAgent-0）：**纵向互补**。HoloAgent-0 在 agent 层做 reason-tool-feedback-replan + 3D 空间记忆；ZR-0 在 policy 层把“推理”压缩进 VLA 表示。可作“高层 agent 规划 ↔ 低层 VLA 执行”的串读。

## 可追问点

1. **“无性能损失”缺对照实验**：论文没有做“推理时生成 ECoT vs 跳过 ECoT”的直接对比。虽然 attention mask 让二者对 action expert 数值等价，但 VLM 在“被要求生成 ECoT”与“只编码 prompt”两种前向下，last-layer hidden states $f_t$ 会完全一致吗（因果 vs 双向、是否有 ECoT 占位 token）？值得回看架构细节确认。
2. **1:3 self:cross 比例无消融**：作者主张它比 GR00T N1 的 1:1 更利于跨模态吸收，但没给该比例的 ablation。1:2 / 1:4 会怎样？
3. **消融只在 LIBERO**：Table 5 的 “w/o ECoT PT” 只覆盖单臂、且套件多已饱和（−2.1 均值）。在 RoboCasa 那种更未饱和、Close 任务弱的设置上去掉 ECoT PT，掉分会不会大得多？跨本体收益的量级需要更全的消融。
4. **推理延迟口径**：§3.4（A6000, 90ms）与 §6（H100, 100ms）不一致，究竟哪台卡、哪个数字？
5. **Close 任务与精细控制的短板**：RoboCasa 的 6 个 Close 任务、真实 Hang Cups 都弱于对手。作者归因于“预训练数据里罕见 / 更吃动作监督规模”——这是否意味着 ECoT 对齐对“低层动力学要求高、语义结构弱”的技能天然帮助有限？
6. **VL 共训对 OCR 的因果**：Push Blocks +27.9 被归因于 VL 共训 + ECoT 保住文字识别，但没有“去掉 VL 共训”的消融来隔离这两者各自的贡献。

## 我的阅读笔记

这篇的真正主张不是“又一个带 reasoning 的 VLA”，而是把 cross-embodiment 的病因从**动作空间格式**重新定位到**高层推理表示的语义对齐**，并给出一个很克制的工程答案：**把 ECoT 当 dense 预训练监督刻进 VLM，用一条 attention mask 让它在部署时零成本**。最优雅的一点是“推理时跳过 ECoT 无损”不是靠玄学，而是 by-construction——action expert 被掩码挡在 ECoT tokens 之外，生不生成都读不到。这让“reasoning 的收益能不能白拿”这个老问题有了一个干净的架构级回答。

但要冷静看边界。第一，**证据结构偏弱于主张**：全文核心消融只有 Table 5 一张、且只在已饱和的 LIBERO 上，量级 −2.1；“无性能损失”“1:3 比例更好”“VL 共训救 OCR”这些都缺受控对照，更多是设计论证 + 定性归因。第二，**收益有明显能力错位**：pick-and-place 与 long-horizon planning 涨得多，Close 类多阶段交互、Hang Cups 类精细马达控制反而被 π0.5 这类更重动作监督的模型压过——ECoT 对齐帮的是“认知/规划”，不是“灵巧动力学”。第三，**数据效率是真亮点**（RoboTwin 用 1/20 语料打平 LingBot-VLA），但它同时也暴露了本文的现实处境：1,000 小时语料在当前 VLA 竞赛里偏小，作者自己把 scaling 列为头号 future work。

我会把它作为**“结构化推理监督如何进入 VLA 表示、又如何在推理时被无损省掉”**这条线的入口条目，和 [[@kang2026x-tokenizer]]（动作表示接口）纵向对读——一个把对齐放在推理层、一个放在动作层；再和 [[@wu2026tactile-wam]] 横向对读它们共享的“非对称注意力掩码隔离训练信号”这一手法。等要评估 ECoT 的可扩展性，重点回看 ProcCorpus-60M 的 ProcVLM 标注流水线是否稳定、以及“选择性帧标注”能不能顶住 dense 标注的质量。
