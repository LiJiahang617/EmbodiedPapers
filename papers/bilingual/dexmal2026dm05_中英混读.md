## 摘要

> [!warning] 原文无 Abstract
> 博客没有正式摘要。本节由 Overview（整体介绍）小节压缩而成，不是原文摘录。

DM0.5 是 Dexmal 继 DM0（2026 年 2 月发布的第一代原生具身基础模型）之后的迭代版本。作者的问题意识是：真实世界对机器人的要求远高于一个精彩 Demo——通用具身基础模型不能只在固定场景完成既定任务，而要真正理解指令语义、理解「接下来为什么要这样做」，并在不同相机视角、物体状态、环境、机器人本体和各类干扰下稳定执行，还要能在少量数据微调后快速适应新任务。

DM0.5 的回答不是把模型和数据继续放大，而是在四个方向做系统改造：**长历史上下文建模**（Context Abstraction Layer，最长 60s）、**语言化的具身推理**（Embodiment CoT，11 种自回归任务）、**动作监督的时间对齐**（Trajectory Alignment Layer，DP 单调匹配）与**数据清洗管线**（五道过滤）。自述五项核心提升：Zero-Shot 能力涌现、Fine-Tuning 高效可靠、60s 长记忆、动作鲁棒、多机型后训练迁移。

## 论文主线

全文是一条「**把 VLA 从 Markov 策略改造成有进程感的策略**」的论证链：

1. **立问题**（Overview）：DM0 证明了范式可行，但只在可控环境；开放世界要求指令理解 + 跨视角/跨本体/抗干扰 + 少样本适配。
2. **归因**（Model Overview）：把差距归到四个可操作的技术缺口——缺历史、缺推理监督、动作监督有时间噪声、数据脏。注意这一步是作者的**断言**，博客没有给出「这四项就是瓶颈」的诊断性实验。
3. **给方案**（三个 Layer + 训练/推理）：每个缺口对一个模块，Context Abstraction 补历史，Embodiment CoT 补推理，Trajectory Alignment 补监督对齐，数据清洗补数据。
4. **给证据**（Experiments）：Zero-Shot 对比 → Fine-tuning 三类基准（真机 / 仿真操作 / 仿真导航）→ 长记忆专项真机实验 → 鲁棒性（相机 9 组 + 人为干扰）。
5. **收束**（Conclusion）：开放世界不是把更多任务装进模型，而是「拒绝用任务表冒充世界」。

主线的**结构性弱点**：第 3 步的四个模块和第 4 步的总体指标之间没有消融连接。全文没有任何一处把某个指标的提升归因到某个具体模块（唯一接近的是长记忆专项实验，且只有定性描述）。

## §1 Overview / 整体介绍

**本节如何推进论证**：把「VLA 已经做到什么」和「开放世界还要什么」之间的差摆出来，作为全文的问题设定。

作者先承认过去两年 VLA 的成就：机器人不再只按固定程序执行动作，而是开始理解自然语言指令、识别开放世界物体、把视觉语义转成可执行控制信号。DM0（2026 年 2 月）是他们第一个从零搭建的 embodied-native foundation model（原生具身基础模型），在**可控环境**下学会了一系列复杂操作任务。

转折点在于：真实世界的要求远高于一个 Demo。作者列了五个「不同」——不同相机视角、不同物体状态、不同环境、不同机器人本体、各类干扰——外加「少量数据微调后快速适应新任务」。这五条后来一一对应到实验章节，结构上是自洽的。

五项核心提升（原文措辞）：

1. **Zero-Shot 能力涌现**——让 VLA 基础模型在真正未知的开放环境按自然语言指令完成任务；
2. **Fine-Tuning 高效可靠**——更强基座带来更强下游专家模型，训练效果更好且成本更省；
3. **长记忆能力**——架构上支持历史信息学习，最长 60s；
4. **动作更加鲁棒**——面对光照、相机视角变化、人为主动干扰；
5. **多机型支持**——多机型多任务训练，可后训练迁移到未见机型。

**关键证据 / 图表 / 公式**：本节只有四个演示视频的图题（开放环境桌面整理、跨容器与空间关系理解、复合目标与约束指令执行、多步堆叠与精细对齐）。**注意**：这四个是 demo 视频，不构成量化证据。

## §2 Model / 模型

### §2.0 Overview

**本节如何推进论证**：给出架构规格，并明确「提升不来自 scaling」这一定调，为后面三个 Layer 铺路。

DM0.5 沿用 VLA 架构：**4B VLM 作为多模态主干 + 680M Action Expert 生成连续机器人动作**。作者强调，相比 DM0，重点不只是扩大模型和数据规模，而是在**历史上下文、具身推理、动作监督和数据质量**四处做系统增强，使模型「从当前帧驱动的操作策略，升级为能够理解任务进程、处理开放指令并稳定输出连续动作的机器人基础模型」。

![[papers/images/dexmal2026dm05/model_overview_en.png|700]]

架构图值得逐块读（这张图信息密度远高于正文）：

- **左半：VLM 4B**。上下两行 token 序列分别是输入与输出侧。绿色 token 来自 Context Abstraction 的图像序列，黄色 token 是结构信息与指令，虚线框 token 对应 Embodiment CoT Tasks（图中标出 **Task Planning / EE Prediction / Action Generation** 三类，与正文的三分类对应，其中 EE Prediction 对应正文的「事件与环境预测」），灰色 token 是 Robot State。
- **中间接口：KV cache**。Action Expert 通过 KV cache 读取 VLM 的上下文，而不是重新编码——这是把 4B 主干与 680M 专家解耦的关键工程点，正文未展开。
- **右半：Action Expert 680M**，输入 noisy actions，输出 **Action Velocity field（动作速度场）**——这是 Flow Matching 的标准形式：学的是从噪声到真值动作的速度场而非动作本身。
- **底部四块输入**：Context Abstraction（图像序列 → 压缩 token）、Structure Information & Instruction（图中示例为 `Embodiment: dosw1 / Control mode: joint / Overall Speed: 0.1` + 指令 `pick up the blue bowl and then place it in the red bowl, and then robot arm homing`）、Embodiment CoT Tasks、Robot State。
- **右下：Action Alignment** 小图直观画出 Ground Truth 与 Prediction 两条轨迹的锚点连线，正是 §2.3 的机制。

> 从架构图能读到但正文没写的两点：(1) **控制模式（joint）和整体速度（Overall Speed: 0.1）是作为结构化文本输入模型的**，这意味着速度可在推理时被指定；(2) 机器人本体以 `Embodiment: dosw1` 这样的**标识符**进入 prompt，这是多机型统一建模的实现方式。

### §2.1 Context Abstraction Layer：历史信息融合

**本节如何推进论证**：解决「当前帧不够用」的问题，是五项自述提升里「长记忆」的唯一机制来源。

传统 VLA 每个控制步只输入当前图像和当前状态，这对短时、局部、近似 **Markov（马尔可夫）** 的任务够用。DM0.5 引入历史帧，让模型在决策时获得短期情境记忆。推理时模型同时接收当前帧和过去若干关键帧，提供长达 1 分钟的任务进程状态变化。作者举的四个例子很能说明「历史」在具身任务里指什么：

- 物体**从哪里**被拿起（位置记忆）；
- 工具**是否已经**使用（动作完成状态）；
- 某个区域**是否已经**被清理（进度记忆）；
- 机器人**是否已经**经过某个地标（导航记忆——注意这条是为导航任务准备的）。

训练侧的做法：从当前时刻向前采样多个 **history slot**，每个 slot 经**时间采样（temporal sampling）**和**空间抽样（spatial sampling）**合并为**固定数量**的视觉 token。这里「固定数量」是关键工程约束——它让上下文长度不随历史长度线性膨胀。

**鲁棒性设计**：采用**随机历史长度**和**历史增强（history augmentation）**，使模型同时适应长历史、短历史和无有效历史三种输入。作者明确说明目的是「降低模型对固定历史窗口的依赖」，并让模型在历史缺失或部分失效时**优雅退化**到当前观测驱动的行为。这一点在部署上很实际：真实系统里历史帧可能因丢帧、遮挡或重启而不可用。

**关键证据 / 图表 / 公式**：本节无公式、无图。压缩比（多少帧压成多少 token）、slot 数量、采样策略细节全部未给出——这是复现该模块的**主要缺口**。

### §2.2 Embodiment CoT Tasks：广泛的具身推理

**本节如何推进论证**：把机器人数据从「单一动作监督」扩成「指令理解 + 时序推理 + 动作生成」的联合监督，是 Zero-Shot 提升的主要归因对象。

作者坦承具身推理不是新东西（"Embodied reasoning is not new"），但在 DM0.5 里把它做成训练的核心部分。背后理念：具身基础模型需要对**环境变化、指令语义、自身本体状态与行为**有充分建模，而**语言仍是最高效的表示接口**。

具体做法：在机器人数据上引入 **11 种自回归任务**。模型需基于当前图像、机器人状态、任务指令和历史信息，回答**受约束的问题**。三类：

1. **任务规划（Task planning）**——关注当前任务阶段、前后步骤关系、任务进度，让模型理解「现在做到哪一步、接下来该做什么」。
2. **事件与环境预测（Event and environment prediction）**——关注任务边界、状态变化、未来关键事件，增强对场景演化和阶段切换的感知。
3. **动作生成（Action generation）**——关注未来动作或动作语义摘要，使模型在生成连续动作前形成更清晰的**动作意图表征**。

作者对效果的表述是因果性的：模型不只学「当前画面对应什么动作」，还学「**为什么**在当前指令和任务进程下应该执行这段动作」，以及「未来世界状态**会怎么变**」。

**关键证据 / 图表 / 公式**：11 种任务的**具体清单未给出**，只给了三个类别。这是全文最可惜的省略——11 这个数字被反复强调，但读者无法知道是哪 11 种，也无法判断它们与已有 embodied-QA 数据集的关系。架构图里露出的 `Task Planning / EE Prediction / Action Generation` 三个方框是仅有的额外线索。

### §2.3 Trajectory Alignment Layer：动态动作匹配

**本节如何推进论证**：处理遥操作数据的**时间相位噪声**，是「动作更鲁棒」的机制来源。这是全文技术上最有新意的一节。

**问题**：遥操作采集的数据里，同一任务多次采集常有不同执行节奏。如果把预测动作与原始轨迹的**固定时间位置**强绑定，模型容易学到**采集节奏**（rhythm of data collection）或过拟合时序噪声，而不是任务本身的动作规律。

**解法**：把监督从「固定时间点对齐」改为「**轨迹进展对齐**」（align supervision by trajectory progress）。机制分四步：

1. 模型输出**定长**的未来动作片段；数据侧保留**更细粒度**的真值动作轨迹（即真值分辨率高于预测分辨率）。
2. 训练时为每个预测动作在真值轨迹中选一个**动作锚点（action anchor）**。
3. 匹配必须**严格单调递增**：越靠后的预测动作只能匹配越靠后的真值位置，**防止时间反转**。
4. 每个候选匹配的损失由预测动作与真值锚点之间的误差计算；整体匹配用**动态规划（dynamic programming）**求解，使所有预测动作的总匹配损失最小。

**防退化设计**：为避免匹配只挑「局部容易的动作」，作者进一步考虑**相邻锚点之间的轨迹连续性**——不仅单个动作点要接近，相邻锚点之间的真值轨迹也应能被预测动作的变化合理解释。作者对这个约束的解释是双向的：既**允许合理的速度差异**，又**减少模型跳过关键动作过程的风险**。

**效果表述**：降低时间相位噪声，使模型更关注**抓取、对准、接触、释放**等任务关键动作变化，从而使学到的**动作速度场（action velocity field）更平滑更鲁棒**，提升跨采集员节奏的泛化。

> 这套机制在形式上等价于对预测序列与真值序列做一次带单调约束和平滑项的 **DTW（Dynamic Time Warping，动态时间规整）**，只是把距离项换成动作误差、并加了轨迹连续性正则。博客没有点破这层联系，也没有给公式。

**关键证据 / 图表 / 公式**：**全文无公式**。匹配损失的具体形式、连续性项的定义与权重、DP 的状态转移方程均未给出。架构图右下的 Action Alignment 示意图是唯一的可视化。这一节**无法据此复现**。

### §2.4 Training / 训练

**本节如何推进论证**：说明四类数据如何各司其职，以及为什么要分组学习率。

训练策略核心是**多源数据对齐后的混合训练（multi-source mixture training after data alignment）**，四类数据分工明确：

| 数据类型 | 承担的能力 |
| --- | --- |
| 机器人操作数据 | 动作学习的主体监督 |
| 视觉语言数据 | 维持视觉主干的开放词表理解与空间推理 |
| 导航数据 | 长指令理解与路径决策监督 |
| 视频理解数据 | 时序建模、事件理解、动态场景表征 |

**优化策略**：VLM 主干与 Action Expert 采用**分组学习率**——主干用**较小**学习率以降低灾难性遗忘、稳定保留通用视觉语言能力；Action Expert 用**更大**学习率以充分学习机器人动作分布。训练用混合精度和分布式优化，并对 Action Expert 做独立优化，以支撑长上下文、多相机输入和 history token 带来的额外计算开销。

**关键证据 / 图表 / 公式**：无具体学习率数值、无 batch size、无训练步数、无数据配比、无算力规模。训练章节实质上只有定性描述。

### §2.5 Inference / 推理

**本节如何推进论证**：给出部署侧的硬指标，这是全文少数几个可直接对标的工程数字。

- 推理以 **action chunk** 为单位；
- 默认 **10 个 diffusion / Flow Matching steps** 生成一个 **50 步 chunk**；
- 优化后：**NVIDIA RTX 4090 单卡 10 Hz**，**NVIDIA H100 单卡 20 Hz**。

## §3 Data / 数据

### §3.1 数据构成

DM0.5 用大规模异构数据预训练，覆盖四类来源：

1. **机器人操作数据**：多种本体的真实操作数据，明确列出 **AgileX（松灵）ALOHA、Galaxea R1 Lite、AgiBot G1、Franka Emika Panda、UR5、ARX5**，以及 **Dexmal 自研双臂移动操作机器人**。
2. **具身导航数据**：一系列开源视觉语言导航（VLN）与开放词汇导航数据集，加上**自采集 3D 重建场景**下的导航数据。
3. **第一人称人类操作数据**：采自日常生产环境的人类第一视角操作，含手部交互、工具使用、物体操作和细粒度原子动作。
4. **通用多模态视觉语言数据**：图像、视频、视觉指令数据，并构建**自动生成管线**增强——中文版给出四个具体目标：**空间定位、未来状态预测、动作后果分析、反事实推理**。

> **数据规模全文未披露**：没有小时数、轨迹条数、样本量或各源配比。（站外报道称约 15 万小时，但该数字**未经主源确认**，不应写进笔记当事实。）这是评估「Fine-Tuning 更省成本」这一主张的根本障碍。

### §3.2 数据清洗策略

五道清洗，是全文写得最具体的一节：

1. **异常值去除（Outlier removal）**：ROS 记录中偶发极大/极小/突变值。过滤明显超出物理可达范围或违反运动连续性的样本。**额外做跨模态一致性检查**——剔除「图像画面有明显移动或摇动、但机器人状态与动作记录未体现相应运动」的片段。这条是防时间戳错位/丢包的实用手段。
2. **静止帧去除（Static-frame removal）**：图像与状态长时间静止的片段动作信息量有限，降低训练效率，且**可能影响部署时的动作响应能力**（模型学会「不动」）。训练前移除长静止段，提升有效动作密度。
3. **无价值动作去除（Low-value action removal）**：执行不到位、意图不明确、与当前任务目标无关的行为片段，会引入噪声监督。
4. **动作模式去重（Action-pattern deduplication）**：针对 **ALOHA 这类平台，不同关节组合可能对应近似等价的末端运动模式**（即冗余自由度带来的多解）。去重等价运动模式，只保留统一一致的关节表示，避免模型学到互相冲突的关节映射。**这是全文对具体硬件缺陷最有针对性的一条。**
5. **错误标注重新标注（Relabeling）**：构建自动化重标管线，通过**跨模态一致性校验**修正子任务标签。作者强调优点是「**不大量丢弃数据的前提下**修正错误标注」，提升标签可靠性与数据利用率。

**关键证据 / 图表 / 公式**：五道清洗全部无阈值、无过滤比例、无消融。「清洗提升了动作监督稳定性」是断言而非结论。

### §4.3 历史记忆能力

**本节如何推进论证**：这是全文唯一直接验证某个具体模块（Context Abstraction）的实验，尽管只有定性结果。

作者先说明为什么需要它：具身任务的许多关键条件**不出现在当前帧**——物体可能已被移动，桌面状态会因动作改变，任务规则可能只在 episode 早期通过人类示范出现。两个真机实验对应互补的时间尺度：

**实验一「拿起杯子擦桌子」（短程记忆）**：机器人先拿起杯子使其下方桌面暴露 → 擦拭桌面 → **把杯子放回最初位置**。杯子被拿起后，当前画面已不含其初始位置信息。中文版明确了仅靠当前帧的三种失败模式：**随机放置、靠近当前位置放置、放置偏移较大**。DM0.5 通过历史视觉记忆恢复初始位置并完成复位。

**实验二「人类示范学习」（长程记忆）**：任务开始时人类先做一次**规则展示**，机器人需观察示范中电池的放置方式，并在后续执行阶段**保持这一规则**。与擦桌不同，决策依据不在当前视野，而依赖**早期示范与当前执行状态之间的关联**。DM0.5 使用**超过一分钟**的历史视觉信息，把早期示范转化为后续操作策略，并跨阶段保持规则一致性。

**作者的结论**：两个实验说明预训练阶段形成的情境记忆表征**可以在下游 SFT 中被激活**，并参与视觉语言条件下的动作预测。

> **中文版独有的关键推论**：在「人类示范学习」下，**Video Prompt 能够成为一种新的指令表述形式**，让机器人以 **In Context Learning** 的方式完成新任务。这是全文最有想象力的一句——它把「长记忆」从一个鲁棒性特性重新定位成一种**新的任务指定接口**：不写指令，直接演示一遍。英文版完全没有这段。

**关键证据 / 图表 / 公式**：三个演示视频图题，**无成功率、无 baseline、无消融**。「关掉历史会怎样」这个最该做的对照实验没有做——擦桌任务的三种失败模式是描述性的，而非测量出来的。

**最有价值的发现是行为层面的**：作者观察轨迹后指出模型呈现**明确的两阶段策略**——

1. **粗定位阶段**：依据**第三视角相机**的全局场景信息，把末端执行器引导到目标物体附近；
2. **精调阶段**：以**腕部固定相机**的局部视觉反馈为核心，执行精细位置调整与对齐。

当第三视角相机处于极端位姿（左三、右三）时，第一阶段的空间偏差显著增大，但**腕部相机的局部精调能力能补偿该偏差**，绝大部分试验仍成功。

> 这个两阶段分工是**涌现的而非设计的**——模型自己学会了「远处看全局、近处看手腕」，并且腕部相机（相对末端固定，因此视角不受第三视角扰动影响）成为鲁棒性的锚。**这解释了为什么成功率只在 80%–100% 波动**：真正的不变量（腕部视角）始终在。
>
> 反过来说，这也意味着**该实验只测了第三视角的鲁棒性，没测腕部相机变化的鲁棒性**——而后者才是真正的难点。同时 8/9 组配置落在 80–90% 这个 10 次试验的粒度上（即 1–2 次失败），**10 次试验的分辨率不足以区分 90% 与 80%**。

#### 人为干扰

Dexmal-Mirror 真机测试。结果：**人为移动目标**以及**短时遮挡**下，模型仍能保持场景理解并推进任务。当**容器位置和朝向发生变化**后，模型不依赖原始固定轨迹，而是根据新的视觉状态**重新调整末端位置与动作方向**，继续完成操作。

作者的解释：模型能在外部扰动改变物体—容器—机械臂空间关系后**重新建立三者的空间对应关系**，避免任务中断。能力来源归为「大量丰富的真机数据 + 对视觉状态/空间关系/动作映射的高效学习」。

**关键证据 / 图表 / 公式**：两个演示视频图题，**纯定性，无成功率、无干扰强度分级、无 baseline 对比**。

## §5 Conclusion / 结语

**本节如何推进论证**：从技术收束到方法论主张。

作者的核心命题：「面向开放世界的能力建设，不是把更多任务装进模型，而是**拒绝用『任务表』来冒充『世界』**」（rejecting the fiction that a task list can stand in for the world）。让模型跳出「剧本环境」，尽最大可能让开放世界本身成为训练环境，是走向通用具身智能的最快路径。

英文版多出一段更完整的展望：今天仍需采集机器人数据、设计任务、构建评测；未来希望**真实世界本身成为最好的老师**——每一次交互、每一次尝试、每一次成功和失败都成为机器人理解世界并自我改进的一部分。最终机器人不应只是复现见过的动作，而应用对世界的理解去完成**从未被写进剧本**的任务。

> 这段主张与 DM0.5 的实际做法之间存在张力：DM0.5 仍是**纯离线模仿学习**（遥操作数据 + 清洗 + 混合训练），没有任何在线交互、试错或自改进机制。「让世界成为老师」是愿景陈述，不是本作已实现的能力。库内 [[@intelligence2025pi06-vla-that-learns]]（π*0.6/RECAP，经验强化学习自改进）和 [[@xiao2026enpire]]（策略自改进）才是在这条线上真正动手的工作。

## 局限与可追问点

1. **无消融，是全文最大的方法论缺口**。Context Abstraction / Embodiment CoT / Trajectory Alignment / 数据清洗四者的贡献完全未拆分。作为技术博客可以理解，但这意味着「哪个设计真正有用」无法从本文得到答案。
2. **Zero-Shot 只有柱状图**。既然是作者自述的「核心提升维度」，却是全文证据最薄的一节——没有数值表、没有任务清单、没有 trial 数。
3. **`status` 维度的退化未被讨论**。Franka 上 DM0.5 在 status 约束的成功率明显低于 Pi0.5-Droid，正文的「绝大多数维度显著优于」把它盖过去了。可追问：是历史上下文干扰了对**当前物体状态**的判断吗？（长历史可能让模型用「过去的状态」而非「当前状态」作答，这正是记忆机制的典型副作用。）
4. **R2R 的 SPL 落后**值得深究：SR 最高而 SPL 第四，说明路径效率不佳。是否长历史让模型倾向于更多探索/回看？
5. **60s 这个数字的代价没有交代**。历史 token 如何缓存？推理帧率（4090 10Hz）是否已包含满历史的开销？满历史与空历史的延迟差是多少？
6. **DM0.5-Nav 与 DM0.5 的关系不明**。是同一组权重还是导航专用微调分支？如果是后者，「操作导航统一模型」的说法就要打折。
7. **数据规模完全不透明**，使「更省成本」的主张无法验证。
8. **与最强对手的正面比较缺位**：Table30 v2 只说 SOTA 不给对比表；Zero-Shot 里 Franka 平台比的是 Pi0.5-Droid 而非 π0.7（库内已有 [[@intelligence2026pi07-steerable-generalist-robotic]]）。
9. **「让世界成为老师」与纯离线模仿学习的实现之间存在张力**（见 §5 批注）。

## 精读路线 / 为什么需要回看

**这篇值得回看的理由，不在于它的指标，而在于三处设计判断：**

1. **Trajectory Alignment 的 DP 单调匹配**（§2.3）——把「遥操作节奏差异」当成一个可以在**损失函数层面**解决的问题，而不是靠数据增强或后处理。这个思路可迁移到任何有人类演示节奏噪声的模仿学习任务。**是全文最值得据为己用的一点。**
2. **两阶段视觉分工的涌现**（§4.4）——「第三视角粗定位 + 腕部相机精调」不是设计出来的，是从轨迹里观察到的。这对相机配置的工程选择有直接指导：**保住一个随末端固定的视角，第三视角就可以宽松**。
3. **Video Prompt 作为指令接口**（§4.3，仅中文版）——把长记忆重新解释为一种任务指定方式。这条如果成立，比任何指标都重要。
